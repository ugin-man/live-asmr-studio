# Live ASMR Studio v0.15.1

A reliability update for the existing extension. No additional server, paid API, dependencies, or browser permissions.

## Fixed

- Audio settings now persist through the service worker. Chrome offscreen documents expose `chrome.runtime` only, so direct `chrome.storage` calls from the audio engine were not reliable. See the [Chrome offscreen API documentation](https://developer.chrome.com/docs/extensions/reference/api/offscreen#concepts_and_usage).
- Reopening the side panel on the already captured tab keeps the current audio stream running.
- Start, Stop, and track-ended events are serialized so stale cleanup cannot stop a newer capture or turn audio back on after Stop.
- Motion choice, cycle/transition timing, and manual motion stop are restored on the next connection.
- Movement and timing remain editable during playback. Background polling no longer overwrites pending motion input.
- Settings imports validate values and custom prompt structure. Importing 10× or greater gain requires the same one-time consent as the volume slider; a backup cannot provide that consent.
- The downloadable ZIP now includes the MIT license alongside third-party attribution.

The existing sound defaults, circular position control, and five-language UI and authored prompts are preserved. Ambience still starts off at −34 dB.

## Update

Download `live-asmr-studio-v0.15.1.zip`, extract it, replace the contents of your existing extension folder, then press **Reload** at `chrome://extensions` or `brave://extensions`. If you load the repository's `extension` folder directly, update the checkout and press **Reload**.

Start at a low headphone/system volume. Preserved settings will now actually be restored, including previously saved high gain.

## Verification

Seven automated suites cover localization, authored sessions, capture ownership, the real worker/engine message boundary with runtime-only offscreen access, motion persistence, settings imports, live motion controls, ambience, and passive measurement. ZIP contents, MIT license, CRC, and SHA-256 are checked by the packaging script. Web Audio/Chrome hardware is simulated in these tests; this release was not live-listened in the user's browser.
